## 1. 개념

### 1.1 한 줄 정의

**AI-Ready Data는 "사람이 해석하도록 만든 데이터"가 아니라 "기계(모델·에이전트)가 추론하도록 만든 데이터"다.**

기존 데이터 웨어하우스/BI는 정제·모델링·문서화까지만 책임지고, 의미 해석과 판단은 **분석가가** 덧붙였다. "EMEA 매출"을 보면 사람은 어떤 국가가 EMEA인지, 어떤 통화로 환산할지, 어떤 매출 정의(인식 시점/환불 차감 여부)를 쓸지를 맥락으로 안다. 반면 LLM 에이전트는 그 판단 근거가 **데이터와 메타데이터에 명시적으로 내장돼 있지 않으면** 추측하거나 환각한다.

업계에서 통용되는 정의를 종합하면, AI-Ready Data는 다음을 만족하는 데이터다:

- **발견 가능(discoverable)** 하고 **실시간 접근 가능(accessible)**
- 단일 ID·정책 모델로 **거버넌스**되며
- **고품질**이고
- 시스템 간 복사·이동 없이 **에이전트·코파일럿이 소비할 수 있는 재사용 가능한 데이터 프로덕트**로 제공된다

### 1.2 BI-Ready ≠ AI-Ready

이 구분이 핵심이다. BI 성숙도가 높은 조직(시맨틱 레이어 정의됨, 계보 존재, 카탈로그 채워짐, 품질 점수 양호)이 AI 파일럿에서 줄줄이 실패하는 패턴이 2026년 내내 관찰됐다. 대시보드는 잘 돌아가는데, 에이전트는 "지난달 EMEA 톱 제품"을 물으면 지표를 환각하거나 지역 필터를 잘못 적용하거나 출처를 추적할 수 없는 숫자를 내놓는다.

원인은 모델이나 프롬프트가 아니라, **데이터가 사람이 해석하도록 만들어졌지 기계가 추론하도록 만들어지지 않았기 때문**이다. 사람에겐 충분한 맥락이 기계에겐 부족하다.

| 구분 | BI-Ready | AI-Ready |
|---|---|---|
| 소비 주체 | 분석가(사람) | 모델·에이전트(기계) |
| 맥락의 위치 | 분석가의 머릿속/문서 | 데이터·메타데이터에 명시적으로 내장 |
| 의미 정의 | 암묵적, 화면 옆 주석 | 기계 판독 가능(machine-readable) 시맨틱 |
| 신뢰 근거 | "대시보드가 맞겠지" | 추적 가능한 계보·출처 |
| 실패 양상 | 잘못된 차트 | 환각, 추적 불가, 정책 위반 |

### 1.3 왜 지금

- Gartner는 2026년까지 **AI-Ready Data 기반이 없는 AI 프로젝트의 60%가 폐기**될 것으로 전망했다.
- Cloudera/Harvard Business Review가 2026년 3월 발표한 IT 리더 1,574명 대상 조사에서 데이터가 **AI에 완전히 준비됐다고 답한 조직은 7%**에 그쳤다.
- 2026 Gartner D&A Summit은 **"컨텍스트(context)"를 엔터프라이즈 AI의 핵심 인프라**로 규정했다. 시맨틱 레이어·온톨로지·지식그래프를 묶은 "컨텍스트 레이어"가 화두였고, 데이터의 출처·품질·적합성을 기계 판독 가능 포맷으로 기록하는 **"데이터 영양성분표(data nutrition label)"** 개념이 주목받았다.

## 2. 구성요소

AI-Ready Data는 단일 기능이 아니라 여러 속성의 합이다. Gartner가 짚은 3대 축(메타데이터 관리 · 데이터 품질 · 데이터 관측성)을 포함해, 실무에서 챙겨야 할 요소를 정리하면 다음과 같다.

### 2.1 품질 (Quality)

오류·중복·결측이 정제·검증된 상태. 단발성 클렌징이 아니라 **DQ 룰 + 데이터 관측성(observability)** 으로 지속 감시한다. 핵심 지표: completeness, uniqueness, validity, freshness, 스키마 드리프트 탐지.

### 2.2 구조·표준화 (Structure)

모델이 일관되게 처리할 수 있는 표준 포맷·스키마·타입·단위. 통화·시간대·코드 체계가 소스마다 다르면 에이전트가 합칠 수 없다. 명시적 스키마와 타입 강제가 전제.

### 2.3 메타데이터·시맨틱 (Context)

가장 결정적인 축. 컬럼·테이블의 **비즈니스 의미, 정의, 단위, 허용값**을 기계 판독 가능하게 기술한다. 여기서 **시맨틱 레이어(메트릭 정의)** 와 **온톨로지/지식그래프**가 등장한다. "revenue"가 무엇이고 "EMEA"에 어떤 국가가 속하는지를 데이터 옆에 둔다.

### 2.4 계보·설명가능성 (Lineage & Explainability)

데이터가 어디서 와서 어떻게 변형됐는지(provenance). 에이전트가 답의 근거를 **어느 스냅샷·어느 소스로 거슬러 추적**할 수 있어야 규제 대응(EU AI Act 등 투명성·설명가능성)과 신뢰 확보가 가능하다.

### 2.5 거버넌스·접근제어 (Governance)

단일 identity·policy 모델. row-level / column-level 보안, PII 마스킹, 감사 로그. AI 거버넌스와 데이터 거버넌스가 **같은 메타데이터 기반**에서 일관되게 적용되는 것이 2026년 권고 방향이다.

### 2.6 발견 가능성·접근성 (Discoverability & Accessibility)

데이터 카탈로그로 자산을 찾을 수 있고, 복사·이동 없이 실시간으로 질의·소비할 수 있어야 한다. **데이터 프로덕트**로 패키징해 재사용성을 높인다.

### 2.7 AI 전용 가공 (AI-Specific Provisioning)

기존 데이터 관리 위에 AI용 가공을 반복적으로 얹는다: **벡터 스토어, 청킹(chunking), 임베딩(embedding), 샘플링, RAG 연동, 피처 스토어**. 정형 데이터는 시맨틱·SQL 경로로, 비정형 데이터는 임베딩·검색 경로로 나뉜다.

## 3. 동작 방식

### 3.1 레이어드 아키텍처

AI-Ready Data는 스토리지부터 소비까지의 레이어가 맞물려 동작하며, **거버넌스·메타데이터·계보는 모든 레이어를 관통하는 횡단 관심사**다.

```
[6] 소비          에이전트 / RAG / 코파일럿 (질의·추론)
                       ▲
[5] 서빙          벡터DB · 피처스토어 · 시맨틱 API · MCP/SQL 도구
                       ▲
[4] 컨텍스트 레이어  카탈로그 · 시맨틱 모델 · 온톨로지 / 지식그래프
                       ▲
[3] 쿼리          Trino (분산 SQL, 정책 적용 지점)
                       ▲
[2] 테이블 포맷    Iceberg (ACID · 스냅샷 · 스키마 진화 · 파티셔닝)
                       ▲
[1] 스토리지       객체스토리지(MinIO/S3) · 레이크하우스

   ╠══ 횡단: 거버넌스(정책·마스킹·감사) · 메타데이터 · 계보(provenance) ══╣
```

### 3.2 데이터 흐름

1. **수집(Ingest)** — 소스 → 레이크하우스 적재
2. **정제·검증(DQ Gate)** — 품질 룰 통과 못 하면 publish 차단·격리(quarantine)
3. **표준화·모델링** — 스키마·타입·단위 표준화, Iceberg 테이블로 정착
4. **메타데이터·계보 자동수집** — 변환 단계마다 provenance 기록, 카탈로그 등록
5. **시맨틱 매핑** — 비즈니스 정의·온톨로지에 매핑(정형), 청킹·임베딩(비정형)
6. **정책 적용** — row/column 보안·마스킹을 질의 시점에 강제
7. **소비** — 에이전트가 시맨틱 정의로 질의 생성 → 실행 → 결과 + 계보 첨부

핵심은 **"맥락과 신뢰가 데이터와 함께 흐른다"** 는 점이다. 에이전트가 받는 것은 raw 테이블이 아니라, 의미가 붙고 정책이 적용되고 출처가 추적되는 데이터 프로덕트다.

## 4. 실제 구동 예

### 예 1 — 에이전트의 비즈니스 질의: "지난달 EMEA 톱 제품?"

Iceberg/Trino/Airflow 스택 기준으로 end-to-end 흐름.

**(1) 테이블 — Iceberg**  
`sales` 테이블이 `PARTITIONED BY (dt, bucket(16, product_id))` 로 구성. 스냅샷·매니페스트가 있어 "어느 시점 데이터"인지 특정 가능.

**(2) 품질 게이트 — Spark + Airflow**  
일배치에서 null·중복·통화 단위·금액 음수 여부를 검증. 실패 시 Airflow가 다운스트림 publish를 막고 격리. → 에이전트는 검증 통과한 스냅샷만 본다.

**(3) 시맨틱 정의**  
"EMEA = {특정 국가 집합}", "top product = SUM(net_revenue) 기준 내림차순", "net_revenue = gross − refund" 가 시맨틱 레이어에 명시. → 에이전트가 정의를 **추측하지 않는다**.

**(4) 메타데이터·계보·온톨로지 — morph-kgc → Jena Fuseki**  
HMS/카탈로그의 컬럼 설명에 더해, Trino 뷰를 **morph-kgc RML 매핑**으로 NT/Turtle로 변환해 MinIO에 저장하고 **Apache Jena Fuseki 지식그래프**(Kubernetes)로 서빙. 에이전트는 KG로 `Product`, `Region`, `Order` 엔티티·관계를 해소하고, pySHACL로 제약 위반을 검증한다.

**(5) 거버넌스 — Trino 정책**  
질의 시점에 row-level(사용자 지역 권한)·column-level(고객 PII 마스킹) 정책 적용 + 감사 로그.

**(6) 추론·응답**  
에이전트가 시맨틱 정의로 SQL을 생성 → Trino 실행(MCP/SQL 도구) → 결과에 **사용한 Iceberg 스냅샷 ID·메트릭 정의·KG 엔티티**를 계보로 첨부 → 추적 가능한 답변.

> **대비 — AI-Ready가 아닐 때:** "EMEA" 범위를 모델이 추측, net/gross 혼동, 잘못된 통화 합산, 출처 추적 불가 → 그럴듯하지만 틀린 답(환각).

### 예 2 — 사내 문서 RAG 파이프라인 (비정형)

1. 사내 문서(위키·런북·정책) 수집
2. **청킹** — 의미 단위로 분할
3. **임베딩** — 벡터화 후 벡터 스토어 적재
4. **메타데이터 동시 인덱싱** — 출처 URL·작성일·접근권한·부서를 청크와 함께 저장
5. **권한 필터링 검색** — 사용자 권한에 맞는 청크만 검색·주입
6. 응답에 **출처 청크와 문서 링크**를 함께 제시 → 검증 가능

여기서도 핵심은 동일: 벡터만 넣으면 "검색은 되지만 신뢰·거버넌스가 빠진" 상태다. **출처·권한·신선도 메타데이터가 벡터와 함께 흘러야** AI-Ready다.

## 5. 빠른 진단 체크리스트

- [ ] 에이전트가 핵심 지표(매출·활성사용자 등)의 **정의를 추측 없이** 데이터에서 가져올 수 있는가
- [ ] 답변의 숫자를 **소스·스냅샷까지 역추적**할 수 있는가
- [ ] 품질 검증을 통과 못 한 데이터가 **자동으로 차단·격리**되는가
- [ ] row/column 보안·PII 마스킹이 **질의 시점에 강제**되는가
- [ ] "EMEA", "활성 고객" 같은 비즈니스 개념이 **기계 판독 가능 시맨틱**으로 정의돼 있는가
- [ ] 정형(SQL/시맨틱)과 비정형(임베딩/RAG) 경로가 **둘 다 거버넌스 안에** 있는가
- [ ] 데이터가 **복사·이동 없이** 재사용 가능한 프로덕트로 제공되는가

> 세 개 이상 비어 있으면, 모델·프롬프트가 아니라 데이터 readiness부터 손봐야 할 신호다.
